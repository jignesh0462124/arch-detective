ABSTRACT Security assessment is often treated as a separate activity from software development. Developers may receive vulnerability reports that identify a problem but provide little context about the affected code, its potential impact, or the steps needed to address it. Compliance requirements add another challenge, particularly when technical findings must be connected to documented controls or browser-extension store policies. These gaps make security review difficult to interpret and act upon, especially for s mall development teams. This thesis presents ThreatLens, a web-based platform that brings codebase auditing, threat modeling, compliance assessment, and remediation guidance into a single workflow. Users can submit project archives for analysis and examine saved results through a read-only, editor-style workbench. The platform combines static security checks with language-model-assisted analysis to identify potential weaknesses and provide explanations grounded in available source evidence. Findings include severity, recorded file  locations, relevant code excerpts, and remediation guidance. The workbench connects source files with findings, control mappings, and suggested verification steps. An evidence-based graph helps users explore relationships between findings and affected components without presenting those relationships as confirmed exploitation paths. Security Advisor provides contextual explanations and code suggestions, while keeping proposed changes separate from the uploaded source. Browser-extension reviews extend this workflow to Chrome Web Store and Microsoft Edge Add-ons polici es, distinguishing detected violations from requirements that need manual review or cannot be assessed from the submitted package. ThreatLens also provides saved audit history, finding triage, comparison of compatible extension reviews, and downloadable reports. Workspace authorization, private source storage, evidence redaction, and time-limited source previews support controlled access to sensitive project information. Verification covers automated regressions, access-control checks, report generation, and representative browser workflows; these checks establish functional behavior rather than proving universal vulnerability-detectio n accuracy. The principal contribution is an integrated, traceable review workflow that helps developers move from a reported concern to its supporting evidence, possible remedy, and verification approach. ThreatLens supports informed security decisions, but does not replace manual testing, professional assessment, or official compliance and store-approval processes. Keywords: Codebase Security Auditing; Static Analysis; Threat Modeling; Compliance Assessment; Large Language Models; Secure Software Development.
